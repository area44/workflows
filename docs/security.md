# Security Boundaries

Trust model, input validation, and safe command execution for the composite actions.

## Trust

Composite action inputs (`build-command`, `path`) and repo manifests (`package.json`, `pyproject.toml`, `uv.toml`, `.nvmrc`, `.node-version`, `.bun-version`, lockfiles) are untrusted. Package manager identifiers are sanitized against `/^[a-z0-9_.-]+$/` before execution; anything else falls back to `npm`.

## Command execution

- Bundled entrypoints (`dist/*.mjs`) run directly under Node with no shell wrapper.
- Build and autofix commands run through `@actions/exec` with an explicit binary name and argument array — no `sh -c` / `bash -c`. Shell metacharacters (`;`, `&&`, `|`, `$VAR`, `>`) are treated as literal argument text, not control operators, so command injection is not possible.
- `src/pages/build-command.ts` parses the custom `build-command` string with a quote/escape-aware tokenizer (single quotes, double quotes, backslash escapes) before execution.

## Secret masking

Credentials passed via the runner environment or secret env vars are masked by the runner. Errors avoid dumping raw environment maps into public logs.

## Source vs artifact

`src/` is authoritative; `dist/` is generated by `npm run build` (`vp pack`). The `check-dist` job in `.github/workflows/ci.yml` enforces zero drift between them, so stale or untracked artifacts cannot be committed unnoticed.
